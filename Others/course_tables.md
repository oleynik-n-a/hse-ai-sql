# Учебные таблицы `course`

В основной демобазе `bookings` лежат настоящие связанные данные: билеты, рейсы, аэропорты и самолёты. Это удобно для практических задач, но на тысячах строк трудно впервые увидеть механику `JOIN`.

Поэтому для третьей пары мы добавили три маленькие таблицы в схеме `course`. Их строки не меняются, а результаты запросов легко проверить глазами.

> **Схема** – пространство имён внутри базы данных. Полное имя таблицы состоит из схемы и имени: `course.airports_master`.

---

## `course.airports_master`

Маленький справочник аэропортов:

| `airport_code` | `airport_name` |
| --- | --- |
| `DME` | Domodedovo |
| `SVO` | Sheremetyevo |
| `VKO` | Vnukovo |

Одна строка – один аэропорт в нашем учебном справочнике.

```sql
SELECT *
FROM course.airports_master
ORDER BY airport_code;
```

---

## `course.departures_feed`

Независимая выгрузка событий вылета:

| `departure_id` | `airport_code` |
| ---: | --- |
| 101 | `SVO` |
| 102 | `SVO` |
| 103 | `VKO` |
| 104 | `LED` |

Одна строка – одно событие вылета.

```sql
SELECT *
FROM course.departures_feed
ORDER BY departure_id;
```

Таблицы специально не полностью совпадают:

- `DME` есть только в `airports_master`;
- `LED` есть только в `departures_feed`;
- `SVO` есть в обеих таблицах и встречается в выгрузке дважды;
- `VKO` есть в обеих таблицах и встречается в выгрузке один раз.

Между таблицами намеренно нет внешнего ключа. Представим, что справочник и выгрузка пришли из разных систем: именно такие расхождения мы будем искать через внешние и anti-соединения.

---

## `course.fare_classes`

Два класса обслуживания:

| `fare_conditions` |
| --- |
| Business |
| Economy |

```sql
SELECT *
FROM course.fare_classes
ORDER BY fare_conditions;
```

Три аэропорта из `airports_master` и два класса дают `3 × 2 = 6` комбинаций при `CROSS JOIN`.

---

## Как посмотреть структуру

В `psql`:

```text
\d course.airports_master
\d course.departures_feed
\d course.fare_classes
```

Расширенное описание с комментариями:

```text
\d+ course.airports_master
```

Команды `\d` относятся к клиенту `psql`; точка с запятой после них не нужна.

---

## Доступ

Роль `student` может выполнять `SELECT`, но не может изменять общие учебные таблицы. Для домашних заданий используйте их с полными именами:

```sql
SELECT *
FROM course.airports_master;
```

Схема `course` дополняет `bookings`, а не заменяет её. На маленьких таблицах мы разбираем механику, затем применяем её к настоящей схеме авиаперевозок.

---

## `course.daily_airport_metrics`

Маленький набор дневных показателей для оконных функций:

| `airport_code` | `report_date` | `flight_count` | `revenue` |
| --- | --- | ---: | ---: |
| DME | 2026-09-01 | 5 | 12000 |
| DME | 2026-09-02 | 6 | 12000 |
| DME | 2026-09-03 | 8 | 20000 |
| SVO | 2026-09-01 | 7 | 10000 |
| SVO | 2026-09-02 | 9 | 15000 |
| SVO | 2026-09-03 | 8 | 15000 |
| SVO | 2026-09-04 | 4 | 9000 |
| VKO | 2026-09-01 | 3 | 8000 |
| VKO | 2026-09-02 | 4 | 11000 |
| VKO | 2026-09-03 | 6 | 14000 |

Одна строка – показатели одного аэропорта за один день.

В данных специально есть:

- несколько аэропортов для `PARTITION BY`;
- последовательные даты для накопительных расчётов, `LAG` и `LEAD`;
- одинаковая выручка для сравнения `ROW_NUMBER`, `RANK` и `DENSE_RANK` и для peer-групп в `RANGE` / `GROUPS`;
- мало строк, поэтому результат можно проверить глазами.

```sql
SELECT *
FROM course.daily_airport_metrics
ORDER BY airport_code, report_date;
```

Структура в `psql`:

```text
\d course.daily_airport_metrics
```
